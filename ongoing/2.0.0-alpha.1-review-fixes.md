## 17. Show imported memories for this character

**Lane:** Data integrity · **Block**

**Locations:** `Data/DB.lua:81`, `Data/Repository.lua:29`, `Init.lua:22`

**Deliverables:**
- [ ] Memories imported from Memory 1.x are visible on the character who is logged in, or the chat notice says they were stored under a realm and GUID this character does not match. The copy keeps `MemoryAddon_DataSet[realm][guid]` unchanged. The journal only opens `GetRealmName()` plus `UnitGUID("player")`. A Forever character will not have the old GUID. The notice still says the import succeeded (`Data/DB.lua:114`).
- [ ] A test imports under a different realm or GUID than the stub character in `tests/lib/wow.lua`. The current import test uses the same identity, so this miss passes.

The rows stay inside `MemoryForeverDB.realms`. They are not deleted. The legacy globals are cleared, so a second import cannot reread them.

## Out of scope

`Trackers/Npcs.lua:37` returns nil when the `npc` unit is a game object and does not fall through to `target`. That is the wanted-poster behavior asserted in `tests/spec/trackers_spec.lua:84`.

`debug` is toggled with `/mem debug` (`Commands.lua:177`). `minimapAngle` is set by dragging the minimap button (`UI/Minimap.lua:27`), so neither needs an Options row.

`Zones.schedule` (`Trackers/Zones.lua:86`) ignores a second zone event during the 0.5 second wait, then `Zones.check` reads the live location. The place you are in when the wait ends is recorded. A place you leave inside that half second is skipped because zone text is not reliable until then.

The empty required-event probe in `Trackers/Trackers.lua:51` does nothing if setup fails, and status already says `setup failed`. `Name-Realm` is built in both `Trackers/Group.lua:15` and `View/Tooltip.lua:55`. That is a drift risk, not a current miss.

## Ship decision

**Block 2.0.0-alpha.1.** The import can report success and leave this character's journal empty, because rows stay under the old realm and GUID (`Data/DB.lua:81`). The other lanes are Ready with nits or Pass with gaps. The deletion audit found no player-facing memory type that was removed and left impossible to see, except fights, which cannot use the combat log.

Data integrity confirmed three items already on the list: the silent skipped import, per-place deaths missing after import, and zone stats that ignore subzone-only imports. The import test never leaves the stub character, so it does not catch item 17.

Achievement counts with no view, and deaths missing from the Here timeline, were already on the list.

Architecture agreed with items already on the list: silent skipped import, zone stats that ignore subzone-only imports, and achievement counts with no view. Those stay single rows. Imported leaves, slash settings, tooltips, screenshots, and the combat-log fight replacement are accounted for.

Tests: 75 passed, 0 failed, on a stubbed client. The README in-game checklist is still unchecked. That stays manual QA, not a sprint item.

Security found no network calls, secrets, or exfiltration. Achievement counts are new persisted data versus the upstream screenshot-only behavior; that is documented in the changelog and is not a sprint item.
